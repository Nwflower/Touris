# 杭州、广州两日游素材包

2026-09-12 接入。杭州 6 个景点、7 张照片；广州 6 个景点、6 张照片。每城有 3 套两日路线。资料保存于本仓库，前端无需地图 API 或爬虫。

## 编辑入口

- `prototype/city-hangzhou-guangzhou.js`：景点简介、标签、图片路径、路线、攻略链接和静态偏好规则。
- `prototype/assets/cities/hangzhou/`、`guangzhou/`：贡献者提供的原始图片副本。
- `hangzhou-sources.md`、`guangzhou-sources.md`：官方资料和各 3 篇小红书笔记的链接、摘要、访问状态。
- `image-manifest.json`：图片来源记录。图片作者和许可证未提供，不能用旅游攻略链接代替图片授权。未复制小红书图片或全文。

照片中的“清河坊”牌匾与“良渚博物院”标识已人工目视确认，因此网页采用这两个名称；原始文件名保留在清单。照片其余拍摄细节、作者和授权未独立验证。

## 产品行为与边界

首页快捷入口和目的地卡片可进入杭州、广州；需求表单也支持两城。两城固定生成 2 日路线，表单有提示。选择不同方案后，详情和记忆对照按所选方案生成；日期随出发日顺延。

地图为排版示意坐标，不是经纬度或导航线路；无比例尺和实际交通耗时。路线是根据候选景点整理的建议，不冒充官方完整两日游路线。未填入未经核实的评分、点评量、票价、营业时间或酒店报价。

现有记忆系统继续使用。新城市只对匹配的“减少赶场”“大型综合馆兴趣低”“午后休息”做有限规则调整，引用真实档案或当前反馈的记忆 ID；不把外部攻略作者的偏好当作用户记忆。不匹配的偏好保留路线并显示 0 处变化。该素材版本尚未实现任意偏好的智能规划。

## 验证

在 `prototype` 目录执行 `node _verify.js`。检查五城的数据引用与页面渲染、新城市六套路线的选择一致性、跨年日期、两日对照、本地图片路径和偏好变化。浏览器检查步骤：

1. 从首页进入杭州，选择古寺文博型，核对灵隐寺、西湖、良渚博物院及 2 日地图。
2. 展开攻略参考，核对原帖标题、作者和来源链接。
3. 通过需求页改为广州，选择西关地标型，核对 5 个景点及照片。
4. 对第 1 天节奏选择“不喜欢 → 太赶”，对照页应将沙面留作备选；关闭记忆后恢复原路线。

## 发布同步

遵循队友新增的唯一开发目录约定：只编辑 `prototype/`，运行根目录 `./sync-pages.sh` 生成发布副本。脚本现已包含两城数据文件与 `assets/cities/` 图片；`./sync-pages.sh --check` 比对源文件与发布文件。根目录发布副本不要单独修改。

## 后续接入

接地图 API 时另增经纬度及交通数据字段，不把当前 x/y 当成经纬度。接攻略采集时保留来源、作者、采集时间、核验状态，并将研究摘要与用户记忆分开。增加真实餐饮与住宿时再补充具体商家和实时信息。
